# AI Agent Quality Platform 5분 시연 영상 설계

## 목적과 대상

이 영상은 포트폴리오 평가자·면접관과 개발·운영 담당자를 대상으로 한다. AI 에이전트의 응답 품질을 반복 가능하게 검증하고, 결과 분석과 운영 모니터링까지 하나의 시스템에서 수행한다는 점을 5분 안에 전달한다.

핵심 메시지는 다음과 같다.

- 여러 품질 평가 과정을 하나의 자동화된 파이프라인으로 통합했다.
- 결과를 수치, 시각화, 이력, 자동 생성 보고서로 추적할 수 있다.
- 인증, 권한, 장애 진단, 접근 제어와 성능시험까지 실제 운영 환경을 고려했다.

## 구성 원칙

메뉴를 나열하지 않고 `평가 준비 → 품질검증 실행 → 결과 분석 → VOC 분석 → 운영 모니터링`의 문제 해결 흐름으로 구성한다. 실제 데이터를 생성하되 QA 테스트는 3건, VOC는 4건으로 제한한다. 실행이 20초를 넘으면 동일 조건의 사전 생성 결과로 전환한다.

## 장면별 시연 및 내레이션

### 1. 오프닝 — 0:00~0:20

설정, 실행, 대시보드, 모니터링 메뉴를 커서로 차례로 가리킨다.

> 이 프로젝트는 AI 에이전트의 응답 품질을 자동으로 검증하고, 결과 분석과 운영 모니터링까지 한곳에서 수행하는 품질관리 플랫폼입니다. 테스트 데이터 관리, 다중 평가 파이프라인, VOC 분석, 성능 및 운영 모니터링을 통합했습니다.

### 2. 설정 — 0:20~0:45

커넥터 모드와 LLM 공급자 목록을 펼치고 Jira와 웹훅 영역을 표시한다. 실제 API 키는 입력하거나 노출하지 않는다.

> 저장된 응답을 평가하거나 실제 챗봇 API를 호출할 수 있으며, OpenAI와 Anthropic뿐 아니라 OpenAI 호환 사내 모델도 연결할 수 있습니다. 실패율 조건에 따라 Jira 티켓을 생성하고 실행 결과를 협업 채널로 알릴 수도 있습니다. 민감한 연결 설정은 관리자만 접근할 수 있습니다.

### 3. 데이터 준비 — 0:45~1:20

설정에서 데이터셋을 업로드하고 실행 화면에서 테스트 케이스를 업로드한다. 완료 체크리스트와 현재 활성 파일 표시를 확인한다.

> 데이터셋에는 정답과 필수 키워드 같은 채점 기준을 저장하고, 테스트 케이스에는 실제 사용자 발화문을 분리해 관리합니다. 같은 기준값으로 질문 표현만 바꿔 반복 검증할 수 있으며, 업로드 이력과 미리보기 기능도 제공합니다.

테스트 케이스는 다음 3건을 사용한다.

1. `TC-001`: 수강료는 얼마인가요?
2. `TC-002`: 환불은 언제까지 가능한가요?
3. `TC-003`: 필요한 제출 서류를 알려주세요.

### 4. QA 파이프라인 실행 — 1:20~2:05

`rag`와 `llm_quality`를 선택한다. 리허설에서 제한 시간 안에 안정적으로 완료될 경우에만 `regression`도 선택한다. QA 파이프라인을 실행하고 진행률과 단계별 상태를 표시한다.

> 이번 시연에서는 검색품질과 근거성, LLM 품질 판정을 함께 실행하겠습니다. 파이프라인은 챗봇 응답을 수집한 뒤 정답 기준과 비교하고, 검색 정밀도와 재현율, 근거성, LLM 판정을 단계별로 수행합니다. 현재 진행률과 각 단계의 성공 여부는 실시간으로 확인할 수 있습니다.

### 5. 대시보드와 결함 — 2:05~2:45

개요, 통과율 추이, 카테고리별 통과·실패, 실패 항목과 결함보고서를 차례로 표시한다. 그래프 하나는 `표로 보기`로 전환한다.

> 실행이 끝나면 전체 통과율과 카테고리별 실패 현황이 바로 반영됩니다. 검색품질과 LLM 판정 결과는 여러 시각화로 비교할 수 있고, 모든 차트는 표 형태로도 확인할 수 있습니다. 실패한 테스트는 원인과 함께 결함보고서로 자동 정리되어 후속 조치에 활용됩니다.

### 6. 보고서와 추적성 — 2:45~3:15

CSV·마크다운 다운로드 버튼, 방금 생성된 실행 이력과 Jira 티켓 영역을 표시한다.

> 결과는 CSV와 마크다운 보고서로 내려받을 수 있으며, 실행 조건과 결과가 이력으로 남아 회귀검증에 활용됩니다. 설정된 임계값을 초과하면 Jira 이슈 생성까지 연결할 수 있어 테스트에서 조치까지의 추적성을 확보했습니다.

### 7. VOC 분석 — 3:15~3:55

파일 업로드를 활성화하고 샘플을 업로드한다. 분석 지시사항에 `반복적으로 발생하는 불만 유형과 우선 개선 과제를 요약해 주세요.`를 입력한 뒤 실행한다. 완료 후 결과 화면에서 새 이력과 품질 지표를 표시한다.

샘플 VOC는 다음 4건을 사용한다.

1. 상담 연결까지 너무 오래 걸렸습니다.
2. 환불 절차 안내가 화면마다 달라 혼란스럽습니다.
3. 답변은 빨랐지만 필요한 제출 서류가 누락됐습니다.
4. 같은 질문을 다시 하니 이전과 다른 답변을 받았습니다.

> 정형 테스트뿐 아니라 실제 사용자 의견도 분석할 수 있습니다. 게시판, Jira 또는 Excel·JSON 파일을 데이터 소스로 선택하고 분석 관점을 직접 지정할 수 있습니다. 분석 결과는 주요 불만 유형과 개선 과제로 정리되며, 독립 품질평가와 교차검증 결과도 함께 추적됩니다.

### 8. 운영 모니터링 — 3:55~4:30

요청량, 오류율, 평균 응답시간, 외부 서비스 Uptime과 엔드포인트 상세를 표시한다.

> 품질 평가는 배포 전 테스트에만 머물지 않습니다. 실제 운영 요청량과 오류율, 응답시간을 추적하고 외부 챗봇 서비스의 가용성도 주기적으로 확인합니다. 이를 통해 품질 저하와 운영 장애를 같은 플랫폼에서 살펴볼 수 있습니다.

### 9. k6 성능시험 — 4:30~4:45

모니터링 애드온에서 대상 URL을 `http://localhost:8000`, 경로를 `/health`, 지속시간을 `10초`로 설정한다. 실행 버튼과 진행 상태를 보여준 뒤 기존 최신 결과와 p95 차트로 이동한다.

> 별도의 모니터링 애드온에서는 내부 서비스에 대한 k6 부하테스트를 웹에서 실행하고, p95 응답시간과 통과 여부, 실행 이력을 관리합니다. 운영 지표는 Prometheus와 Grafana로 장기 추적할 수 있습니다.

### 10. 운영 완성도와 마무리 — 4:45~5:00

사용자 관리, 오류 로그, 접근 허용 IP를 빠르게 전환한 뒤 대시보드 개요로 돌아온다.

> 계정 승인과 역할 관리, 사용자별 테스트 데이터 분리, 관리자 오류 로그, Grafana와 Prometheus 접근 IP 제어도 구현했습니다. 이 프로젝트는 단순한 평가 화면을 넘어 AI 에이전트의 테스트, 분석, 협업, 운영을 하나의 흐름으로 연결한 품질관리 시스템입니다.

## 실패 대응과 촬영 안전장치

- QA 및 VOC 실행이 각각 20초를 넘으면 진행 상태를 설명하고 동일 조건의 사전 생성 결과를 연다.
- 시연 시작 전에 QA와 VOC 결과를 각각 한 번 생성해 둔다. 이 데이터는 장애 대응용이며 촬영의 실제 생성 장면을 대체하지 않는다.
- API 키, 웹훅, 사용자 이메일, 연락처, 내부 주소를 노출하지 않는다. 저장된 비밀값 미리보기 역시 촬영 전에 마스킹 여부를 확인한다.
- k6는 로컬 `/health` 엔드포인트를 대상으로 10초만 실행한다. 촬영 전에 k6 실행 파일과 권한을 확인한다.
- Prometheus 또는 Grafana가 준비되지 않았으면 오류 상태를 노출하지 않고 플랫폼 자체 차트와 기존 k6 결과만 표시한다.
- 브라우저 알림, 자동완성, 북마크 바를 숨기고 화면 확대율은 전체 UI가 잘리지 않는 범위에서 110~125%로 맞춘다.
- 실제 사용자 데이터 대신 전용 데모 계정과 합성 데이터만 사용한다.

## 리허설 합격 기준

- 전체 녹화가 4분 45초~5분 10초 안에 끝난다.
- QA와 VOC에서 촬영 중 새 실행이 시작되고 결과 또는 안전장치 전환이 명확히 보인다.
- API 키와 개인정보가 어떤 프레임에도 나타나지 않는다.
- 핵심 흐름 다섯 단계가 모두 포함된다: 데이터 준비, QA 실행, 결과 분석, VOC 분석, 운영 모니터링.
- 음성 없이 보더라도 커서 동작과 화면 전환으로 현재 기능을 이해할 수 있다.
- 1920×1080 녹화 결과에서 메뉴, 버튼, 주요 수치가 읽힌다.
