# 팀원용 네트워크 접속 가이드

| 항목 | 내용 |
|---|---|
| 목적 | 같은 사무실/네트워크(LAN, Wi-Fi)에 있는 팀원이 자신의 PC/노트북에서 이 서버에 접속하는 방법 안내 |
| 전제 조건 | 서버를 실행 중인 PC와 접속하려는 PC가 **같은 네트워크**에 연결되어 있어야 합니다 |

---

## 1. 서버가 이미 모든 네트워크 인터페이스에서 수신 대기 중입니다

로컬 실행 명령(`python -m uvicorn app.main:app --host 0.0.0.0 --port 8000`, [사용자_매뉴얼](사용자_매뉴얼.md) 3절)과 `Dockerfile`/`docker-compose.yml` 모두 `--host 0.0.0.0`으로 실행되어 있어, `localhost`뿐 아니라 같은 네트워크의 다른 PC에서도 접속할 수 있는 상태입니다. 추가로 코드를 바꿀 필요는 없고, 아래 두 가지만 확인하면 됩니다.

1. 서버 PC의 로컬 IP 주소
2. 서버 PC의 방화벽이 포트 8000 인바운드 연결을 허용하는지

## 2. 서버 PC의 IP 주소 확인

서버를 시작하면 콘솔에 다음과 같이 접속 가능한 주소가 출력됩니다.

```
============================================================
AI Agent 품질관리·운영 모니터링 플랫폼
  Local:   http://localhost:8000       (이 PC에서 접속)
  Network: http://192.168.0.42:8000    (다른 PC에서 접속 시 사용)
============================================================
```

`Network:` 줄의 주소를 팀원에게 공유하면 됩니다. 콘솔을 확인할 수 없다면 직접 조회하세요.

- **Windows**: `ipconfig` 실행 후 "IPv4 주소" 확인
- **macOS**: `ifconfig` 실행 후 `inet` 항목 확인
- **Linux**: `ip addr` 실행 후 확인

## 3. Windows 방화벽 인바운드 허용

서버 PC가 Windows라면, 관리자 권한 PowerShell에서 한 번만 실행하면 됩니다.

```powershell
New-NetFirewallRule -DisplayName "AI Quality Platform" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
```

GUI로 하려면: 제어판 → Windows Defender 방화벽 → 고급 설정 → 인바운드 규칙 → 새 규칙 → 포트 → TCP 8000 → 연결 허용.

## 4. 팀원 PC에서 접속

브라우저 주소창에 서버 PC의 IP로 접속합니다.

```
http://<서버 PC의 IP>:8000
```

예: `http://192.168.0.42:8000`

## 5. Docker로 실행 중인 경우

`docker-compose.yml`이 이미 `ports: "8000:8000"`으로 호스트의 모든 인터페이스에 게시하므로, 컨테이너를 실행 중인 호스트 PC의 IP로 동일하게 접속하면 됩니다. 별도 설정이 필요 없습니다.

## 6. 트러블슈팅

| 증상 | 원인/조치 |
|---|---|
| 접속이 아예 안 됨 (타임아웃) | 방화벽 규칙(3절) 확인, 두 PC가 같은 네트워크인지 확인 (회사 게스트 Wi-Fi나 VPN은 기기 간 통신이 차단된 경우가 많습니다) |
| 연결 거부(Connection refused) | 서버가 `--host 0.0.0.0`이 아니라 `--host 127.0.0.1`로 실행되지 않았는지 확인 |
| IP가 접속할 때마다 다름 | 공유기 DHCP로 IP가 유동적으로 바뀌는 경우입니다. 공유기 관리 화면에서 서버 PC에 고정 IP를 예약하세요 |
| 사내망 밖(재택/외부)에서 접속하고 싶음 | 이 가이드의 범위 밖입니다. VPN, 리버스 프록시, 포트 포워딩 등 별도의 네트워크 구성이 필요하며, 보안 검토 없이 포트를 인터넷에 직접 노출하지 마세요 |
