# 액티브 자막형 포트폴리오 영상 재촬영 설계

## 목적과 대상

Docker Compose와 AWS에서 동작하는 AI Agent 품질관리·운영 모니터링 플랫폼의 기능을 5분 안에 설명한다. 포트폴리오 평가자·면접관에게는 실제 구현 범위와 동작을, 개발·운영 담당자에게는 데이터 흐름과 운영 기능을 보여준다.

기존 영상에서 보이지 않았던 체크박스 선택 상태를 수정하고, 모든 공개·관리 메뉴의 핵심 쓰기 동작을 합성 데이터로 실제 수행한다. 영상에는 항상 기능 자막과 현재 프로세스 설명을 표시하며, 화면 변화가 3초 이상 멈추는 구간을 허용하지 않는다.

## 확정 요구사항

- 모든 체크박스는 클릭 직후 선택·해제 상태가 고대비로 명확히 보여야 한다.
- 마우스는 클릭 위치로 순간이동하지 않고 사람이 설명하면서 조작하는 것처럼 천천히 이동한다.
- 실행 대기 시간을 포함해 시각적 변화가 없는 화면은 3초 이상 지속하지 않는다.
- 화면 하단에 기능 설명, 현재 처리 단계, 처리 결과를 한국어 자막으로 표시한다.
- 등록, 수정, 승인, 권한·상태 변경, 업로드, 실행, 조회, 다운로드, 댓글, 선택, 삭제를 실제 UI에서 수행한다.
- QA·VOC·게시판·관리 데이터는 외부 시스템에 영향을 주지 않는 합성 데이터만 사용한다.
- VOC Improved는 5단계 실제 합성 실행을 보여주고 외부 LLM 미호출과 `LLM Judge: SKIPPED`를 명확히 표시한다.
- Prometheus·Grafana 차트와 AWS CloudFormation의 `CREATE_COMPLETE` 상태를 포함한다.
- 최종 영상은 5분, 1920×1080, 60fps MP4로 제공한다.

## 화면 상호작용 설계

### 체크박스

모든 기본·동적 체크박스에 같은 시각 규칙을 적용한다. 미선택 상태에는 충분한 테두리를, 선택 상태에는 파란 배경과 흰색 체크를 사용한다. 키보드 포커스도 별도 외곽선으로 구분한다. 클릭 직후 약 0.8초 동안 선택 요소 주변에 강조 효과를 표시하되 실제 체크 상태를 가리지 않는다.

적용 범위는 설정 카테고리, 평가기법, 데이터셋·테스트케이스 목록, 게시판 목록, VOC 소스, VOC 교차검증 A~D, k6 선택 옵션과 관리 화면의 체크박스 전체다. 서버에서 목록을 다시 렌더링한 뒤에도 같은 스타일과 상태 표시가 유지되어야 한다.

### 마우스와 클릭

커서는 목표 지점까지 0.4~0.8초 동안 완만한 곡선으로 이동한다. 클릭 전에 0.2~0.4초 머물고 클릭 위치에는 0.5~0.7초의 작은 파동을 표시한다. 텍스트 입력 중에는 커서를 입력 영역 밖으로 옮겨 내용을 가리지 않는다. 빠른 연속 클릭은 피하고, 조작 목적을 자막으로 먼저 알린 뒤 수행한다.

### 정지 화면 방지

모든 3초 구간에는 커서 이동, 스크롤, 체크 변화, 진행률 갱신, 결과 토스트, 차트 변화 또는 장면 전환 중 하나 이상이 있어야 한다. QA·VOC·k6처럼 실제 실행이 긴 구간은 시작과 초기 진행률을 실시간으로 보여준 다음 중간 대기만 시간 압축한다. 실행 완료 상태와 결과는 다시 정상 속도로 보여준다.

## 자막과 프로세스 설명

화면 하단의 고정 안전 영역에 최대 두 줄의 반투명 자막을 표시한다.

1. 첫 줄: 현재 기능과 사용 목적
2. 둘째 줄: 수행 중인 처리 단계 또는 방금 확인된 결과

자막은 UI 버튼이나 표의 마지막 행을 가리지 않도록 화면별로 좌우 위치를 조정한다. 각 자막은 1.5~4초 동안 유지하되 같은 화면이 이어질 때도 처리 단계가 바뀌면 즉시 갱신한다. 클릭 직전에는 수행할 작업을, 클릭 후에는 성공 토스트나 결과값을 설명한다. 영상 파일에는 자막을 번인하고 같은 내용의 UTF-8 한국어 SRT도 함께 제공한다.

## 데이터 흐름과 격리

촬영 시작 전에 고유 접두사가 붙은 합성 계정, 게시글, 댓글, 허용 IP, 외부 모니터링 대상을 준비한다. 브라우저에서 실제 등록·수정 API를 호출하고 UI에 반영된 결과를 확인한다. 삭제 기능을 시연할 대상은 영상 안에서 직접 삭제하며, 남은 합성 데이터는 촬영 종료 후 정리한다.

QA와 VOC는 `demo/video`의 합성 파일을 사용한다. OpenAI·Anthropic API는 호출하지 않으며, VOC 결과에는 합성 실행이라는 설명과 `LLM Judge: SKIPPED`를 함께 표시한다. AWS 화면은 읽기 전용으로 촬영하고 계정·사용자·주소 표시 영역을 크롭한다.

## 실패 처리

- 체크 상태가 화면에 보이지 않거나 클릭과 상태 변경이 일치하지 않으면 해당 UI를 수정한 뒤 처음부터 다시 검증한다.
- 등록·수정·삭제 API가 실패하면 성공으로 편집하지 않는다. 실패 원인을 수정하고 합성 데이터를 초기화한 뒤 해당 구간을 다시 촬영한다.
- QA·VOC·k6 실행이 예정 시간보다 길어지면 완료를 기다린 후 대기 구간만 압축한다. 완료 전 결과 화면을 삽입하지 않는다.
- Prometheus·Grafana 차트가 비어 있으면 트래픽과 스크레이프 상태를 확인해 데이터를 생성한 뒤 촬영한다.
- AWS 화면에 식별 정보가 노출되면 해당 클립을 폐기하고 크롭 상태를 재확인한 뒤 재촬영한다.

## 검증 기준

### 기능 검증

- 모든 체크박스 유형을 선택·해제하고 DOM 상태와 캡처 프레임에서 체크 표시가 일치하는지 확인한다.
- 등록, 수정, 승인, 권한·상태 변경, 업로드, 실행, 조회, 다운로드, 댓글, 선택 삭제의 성공 응답과 화면 반영을 확인한다.
- QA, VOC Improved, k6가 실제 완료 상태를 표시하는지 확인한다.
- Prometheus·Grafana 차트가 빈 화면이 아니며 AWS 스택이 `CREATE_COMPLETE`인지 확인한다.

### 영상 검증

- 1920×1080, 60fps, 정확히 5분인지 확인한다.
- 전체 파일 디코딩 검사에서 오류가 없는지 확인한다.
- 장면 변화 감지와 수동 검수를 함께 사용해 3초 이상 정지 화면이 없는지 확인한다.
- 모든 기능 구간에 기능 자막과 프로세스·결과 설명이 존재하는지 확인한다.
- 대표 프레임뿐 아니라 체크박스 클릭 전후 프레임, 등록 전후 프레임, 실행 시작·완료 프레임을 비교한다.
- 비밀키, 이메일, 토큰, 계정 ID, 공개·내부 IP 등 식별 정보가 모든 프레임에서 가려졌는지 확인한다.
