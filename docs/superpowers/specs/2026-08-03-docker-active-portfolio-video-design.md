# Docker 전체 메뉴 액티비티 포트폴리오 영상 설계

## 목적

Docker Compose로 실행한 AI Agent 품질관리·운영 모니터링 플랫폼의 모든 메뉴를 약 5분 30초 안에 순회한다. 정적인 화면 설명 대신 합성 파일 업로드, QA 파이프라인 실행, 결과 갱신, 보고서 확인, VOC 분석 결과, k6 부하시험처럼 화면 변화가 발생하는 동작을 중심으로 시연한다.

대상은 포트폴리오 평가자·면접관과 개발·운영 담당자다. 외부 LLM 비용과 가용성에 의존하지 않으며, LLM Judge는 `SKIPPED`로 명확히 표시한다.

## 실행 환경

- `docker compose up -d --build`로 `qa-platform`, `prometheus`, `grafana`를 실행한다.
- 앱은 `http://127.0.0.1:8000`에서 촬영한다.
- OBS는 1920×1080 화면을 녹화하고 WebSocket 제어를 사용한다.
- 합성 데이터만 사용하며 API 키, Jira 토큰, 웹훅, 이메일, 내부·공인 IP는 데모 모드에서 마스킹한다.
- 관리자 메뉴 시연을 위해 촬영 전용 로컬 계정 또는 기존 승인된 관리자 세션을 사용한다.

## 촬영 흐름

| 시간 | 화면 | 실제 동작 |
|---|---|---|
| 0:00–0:20 | 시작·전체 메뉴 | Docker 환경임을 표시하고 메뉴 구조를 빠르게 소개한다. |
| 0:20–0:40 | 설정 | 데이터셋 전용 연결 모드와 마스킹된 연동 설정을 보여준다. |
| 0:40–1:10 | 실행 | 합성 QA 데이터셋과 발화 테스트 케이스를 파일 선택 창으로 실제 업로드한다. |
| 1:10–1:45 | QA 파이프라인 | 검색품질 중심 평가를 실제 실행하고 진행률·완료 상태를 보여준다. |
| 1:45–2:15 | 대시보드·보고서 | 통과율, 실패 분포, 검색품질 차트, 실행 이력, 결함보고서와 다운로드 버튼을 시연한다. |
| 2:15–2:35 | 모니터링 | 요청량, 오류율, 응답시간과 Uptime을 확인한다. |
| 2:35–3:15 | 모니터링 애드온 | 애드온 페이지로 정상 이동해 `/health`, 1 VU, 10초 k6 시험을 실행하고 결과 이력을 확인한다. |
| 3:15–3:35 | Prometheus·Grafana | 임베디드 그래프와 운영 대시보드를 스크롤해 보여준다. |
| 3:35–3:55 | 게시판 | 목록, 검색, 작성 UI를 시연하되 게시물 저장은 생략한다. |
| 3:55–4:25 | VOC 분석 | 합성 VOC 파일을 실제 업로드하고 분석 입력 구조를 보여준다. |
| 4:25–4:50 | VOC 결과 | 사전 생성 합성 결과와 `LLM Judge: SKIPPED` 표시를 확대해 보여준다. |
| 4:50–5:15 | 사용자 관리·오류 로그 | 승인·역할·계정 상태와 운영 오류 추적 기능을 설명하되 상태는 변경하지 않는다. |
| 5:15–5:30 | 접근 허용 IP·마무리 | 접근 제어 기능과 Docker 운영 구성을 요약한다. |

## 데모 UI 동작

- 각 단계에서 현재 기능을 분홍색 강조 테두리로 표시한다.
- 브라우저 클릭 지점에는 짧은 리플 효과를 표시한다.
- 하단 설명 패널에는 단계 번호, 기능명, 한 문장 설명을 표시한다.
- 메뉴 이동은 실제 경로를 보존한다. 특히 모니터링 애드온은 `/monitoring-addon?demo=1`로 이동해야 하며 `/?demo=1#monitoring-addon`으로 변환되어서는 안 된다.
- 파일 업로드와 실행 단계에서는 오버레이 자동 진행을 멈추고 실제 동작 완료 후 다음 단계로 이동한다.
- 관리자 메뉴가 비활성인 환경에서는 촬영을 시작하지 않고 인증 상태를 먼저 준비한다.

## 데이터와 외부 서비스 처리

- QA 데이터는 `demo/video/qa_dataset.json`과 `demo/video/qa_testcases.json`을 사용한다.
- VOC 데이터는 `demo/video/voc_samples.json`을 사용한다.
- OpenAI·Anthropic 호출은 수행하지 않는다.
- VOC 결과는 `demo/video/voc_demo_result.json`의 합성 결과를 사용하며 화면에 사전 생성 결과임을 표시한다.
- k6는 Docker 내부에서 앱의 `/health`만 대상으로 1 VU·10초 실행한다. 외부 주소에는 부하를 발생시키지 않는다.

## 오류 처리

- Docker 서비스가 하나라도 비정상이면 녹화를 시작하지 않고 컨테이너 로그와 health 상태를 확인한다.
- 파일 업로드 또는 QA 실행이 실패하면 해당 촬영을 중단하고 원인을 수정한 뒤 처음부터 다시 촬영한다.
- Grafana·Prometheus 임베드가 비어 있으면 프록시 URL과 컨테이너 health를 확인한다.
- 녹화 중 외부 API 오류를 유발하지 않는다. `SKIPPED`는 의도된 비용 통제 상태로 설명한다.

## 검증 기준

- 데모 모드에서 모니터링 애드온 메뉴가 `/monitoring-addon?demo=1`로 이동한다.
- Docker의 세 서비스가 모두 실행되고 health 확인을 통과한다.
- 합성 QA 파일 두 개와 VOC 파일 하나가 화면에서 실제 업로드된다.
- QA 파이프라인과 k6 시험이 실제 완료 상태를 표시한다.
- 모든 공개 메뉴와 관리자 메뉴가 영상에 한 번 이상 나타난다.
- 비밀값과 개인 식별 정보가 모든 프레임에서 가려진다.
- 최종 MP4는 5분 00초에서 6분 00초 사이이며 1920×1080으로 재생 가능하다.
- 한국어 SRT 자막과 화면 오버레이가 영상 흐름과 일치한다.
