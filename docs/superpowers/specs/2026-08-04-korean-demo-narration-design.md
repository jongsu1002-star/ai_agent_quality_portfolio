# 한국어 포트폴리오 영상 내레이션 설계

## 목표

기존 5분 영상과 한국어 자막 75개를 유지하면서, 영상 앞에 세 종류의 시스템 프로세스 소개 화면을 각각 7초씩 추가하고 전체 내용을 차분한 한국어 여성 음성으로 설명한다. 무음 원본 `portfolio-demo-docker.mp4`는 보존하고 총 5분 21초의 `portfolio-demo-docker-narrated.mp4`를 새 산출물로 만든다.

## 21초 시스템 소개 인트로

- 0~7초: 가로형 전체 프로세스 흐름도. `합성 데이터 → QA 실행 → VOC Improved → 품질 분석 → 모니터링 → 운영 관리 → AWS 배포`를 화살표로 연결하고 순서대로 활성화한다.
- 7~14초: 계층형 아키텍처. `사용자·운영자 → FastAPI 품질 플랫폼 → QA·VOC·k6 → Prometheus·Grafana → Docker → AWS`의 의존 관계를 위에서 아래로 보여준다.
- 14~21초: 단계별 카드 애니메이션. `등록·업로드`, `실제 QA`, `VOC Improved`, `관측`, `운영 안전`, `AWS 서비스` 카드를 빠르게 순차 강조한다.
- 기존 영상과 같은 네이비·오션 블루 계열, 흰색 본문, 청록색 성공 강조를 사용한다.
- 모든 화면에는 계속 움직이는 화살표·진행선·카드 강조를 넣어 3초 이상 정지 화면이 없게 한다.
- 각 화면은 1920x1080, 60fps로 생성하며 7초가 끝날 때 짧은 디졸브로 다음 화면에 연결한다.

## 음성 및 동기화

- Windows에 설치된 `Microsoft Heami Desktop`(`ko-KR`, Female)을 사용한다.
- 외부 TTS API를 호출하지 않으므로 네트워크, API 키, 크레딧이 필요하지 않다.
- SRT의 `\\an8` 위치 태그를 제거한 실제 문장만 읽는다.
- 인트로 세 화면에는 각각 7초 분량의 별도 설명 문장을 사용한다.
- 기존 자막 내레이션은 인트로가 끝나는 21초부터 시작하며 각 자막의 4초 슬롯마다 음성을 별도 생성한다.
- 음성이 슬롯보다 길면 FFmpeg `atempo`로 잘리지 않게 압축하고, 짧으면 뒤에 무음을 채운다.
- 각 슬롯을 정확히 4초로 만든 뒤 75개를 연결해 기존 영상용 300초 내레이션을 생성하고, 21초 인트로 음성과 연결해 총 321초로 만든다.
- 최종 음량은 대화 중심 수준으로 정규화하고, 영상은 스트림 복사하며 음성만 AAC 48kHz로 인코딩한다.

## 오류 처리

- 설치 음성이 없거나 SRT 큐가 75개·300초를 완전히 덮지 않거나 인트로 세 화면의 합계가 21초가 아니면 생성하지 않는다.
- 개별 음성 생성이나 FFmpeg 변환이 실패하면 최종 파일을 교체하지 않는다.
- 임시 산출물과 최종 산출물을 분리하고, 검증된 파일만 최종 이름으로 이동한다.

## 검증

- 자막 파서와 4초 슬롯 계산을 자동 테스트한다.
- 최종 영상이 321초, 1920×1080, 60fps인지 확인한다.
- AAC 오디오 스트림이 존재하고 전체 디코딩이 성공하는지 확인한다.
- 대표 인트로 세 구간과 기존 영상의 시작·중간·마지막 구간을 재생 또는 파형으로 확인해 음성 동기화를 점검한다.
- 기존 영상의 단계 카운터, 작업표시줄 제거, 자막, 정지 화면 기준은 그대로 유지한다.
