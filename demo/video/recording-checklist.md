# AI Agent Quality Platform 촬영 체크리스트

## 현재 환경 점검 결과

- [x] Python 3.12.9 및 FastAPI/Uvicorn/Pandas/OpenPyXL 사용 가능
- [x] 핵심 API·UI·VOC·모니터링 테스트 118건 통과
- [x] 촬영 데이터 JSON 및 실제 애플리케이션 로더 검증 완료
- [x] k6 설치 확인: `C:\Program Files\k6\k6.exe`
- [x] 애플리케이션 `/health`, `/`, `/monitoring-addon` 응답 확인
- [x] 1920×1080에서 메인·모니터링 애드온 가로 오버플로 없음
- [ ] Docker Desktop 실행
- [ ] Prometheus 9090 포트 연결
- [ ] Grafana 3000 포트 연결

Docker·Prometheus·Grafana는 현재 사용할 수 없다. 최종 촬영에서도 사용할 수 없으면 플랫폼 자체 모니터링 차트와 저장된 k6 결과만 보여준다.

## 개인정보 및 녹화 환경

- [ ] 실제 사용자 데이터가 없는 전용 데모 계정으로 로그인한다.
- [ ] 합성 데이터만 사용한다.
- [ ] 북마크 바를 숨긴다.
- [ ] Windows 및 브라우저 알림을 끈다.
- [ ] 비밀번호 관리자와 자동완성 팝업을 끈다.
- [ ] 브라우저 다운로드 트레이를 비운다.
- [ ] API 키와 저장된 비밀값 미리보기를 마스킹한다.
- [ ] 웹훅 URL을 마스킹한다.
- [ ] 사용자 이메일과 연락처를 마스킹한다.
- [ ] 내부·공인 IP 및 모니터링 URL을 마스킹한다.
- [ ] 녹화 해상도를 1920×1080으로 설정한다.
- [ ] 브라우저 확대율을 110~125%로 설정하고 모든 버튼이 잘리지 않는지 확인한다.

## 촬영 직전 데이터 준비

- [ ] `설정`에서 `demo/video/qa_dataset.json`을 업로드한다.
- [ ] `실행`에서 `demo/video/qa_testcases.json`을 업로드한다.
- [ ] `rag`와 `llm_quality`를 선택한다.
- [ ] 리허설이 제한 시간 안에 성공했을 때만 `regression`을 추가한다.
- [ ] QA 파이프라인을 실행하고 20초 타이머를 시작한다.
- [ ] `대시보드`에서 개요, 차트 한 개, `표로 보기`, 결함보고서, 실행 이력을 연다.
- [ ] CSV·마크다운 다운로드 버튼을 보여주되 다운로드 트레이가 녹화 화면을 가리지 않게 한다.
- [ ] `VOC 분석`에서 파일 업로드를 켜고 `demo/video/voc_samples.json`을 업로드한다.
- [ ] 분석 지시사항에 `반복적으로 발생하는 불만 유형과 우선 개선 과제를 요약해 주세요.`를 입력한다.
- [ ] VOC 분석을 실행하고 20초 타이머를 시작한다.
- [ ] `VOC 분석 결과`에서 새 이력과 품질 지표를 확인한다.
- [ ] `모니터링`에서 서버 지표와 외부 Uptime을 확인한다.
- [ ] `/monitoring-addon`에서 k6 대상 `http://localhost:8000`, 경로 `/health`, 낮은 동시사용자수, `10초`를 설정한다.
- [ ] 관리자 메뉴를 빠르게 훑고 대시보드로 돌아온다.

## 타임코드별 샷시트

- [ ] **0:00~0:20 — 오프닝:** 전체 메뉴와 시스템 목적
- [ ] **0:20~0:45 — 설정:** 커넥터, LLM, Jira·웹훅
- [ ] **0:45~1:20 — 데이터 준비:** 데이터셋과 테스트 케이스 업로드
- [ ] **1:20~2:05 — QA 실행:** 평가 기법, 진행률, 단계별 상태
- [ ] **2:05~2:45 — 대시보드:** 통과율, 실패 항목, 결함보고서
- [ ] **2:45 누적 점검:** 2분 55초를 넘었다면 설정 스크롤과 Jira 화면을 생략한다.
- [ ] **2:45~3:15 — 추적성:** 보고서 다운로드와 실행 이력
- [ ] **3:15~3:55 — VOC:** 업로드, 분석 실행, 신규 결과
- [ ] **3:55~4:30 — 모니터링:** 서버 지표와 Uptime
- [ ] **4:30 누적 점검:** 4분 40초를 넘었다면 k6 설정만 보여주고 실행하지 않는다.
- [ ] **4:30~4:45 — k6:** 10초 실행 설정과 최신 결과
- [ ] **4:45~5:00 — 마무리:** 관리자 메뉴와 대시보드 복귀

## 대체 흐름

- [ ] QA가 20초 안에 완료되지 않으면 실시간 진행 상태를 보여주고 “실행은 비동기로 계속됩니다”라고 설명한 뒤 이력에서 사전 생성 결과를 연다.
- [ ] VOC가 20초 안에 완료되지 않으면 취소 버튼을 보여준 뒤 이력에서 사전 생성 VOC 결과를 연다.
- [ ] k6를 사용할 수 없으면 10초 실행 폼을 설정한 상태와 저장된 최신 결과만 보여주고 `실행`을 누르지 않는다.
- [ ] Grafana 또는 Prometheus를 사용할 수 없으면 오류 패널로 스크롤하지 않고 자체 모니터링 차트를 보여주며 선택 연동 기능이라고 설명한다.

## 시간 조정 규칙

- 5분 10초를 넘으면 설정 화면 스크롤을 먼저 줄이고, Jira 티켓 영역을 생략한 뒤, 대시보드 차트를 하나만 보여준다.
- 4분 45초보다 짧으면 QA 진행 단계와 실패 케이스 상세 설명을 늘린다.
- 시간을 맞추기 위해 새로운 기능이나 화면을 추가하지 않는다.

## 최종 개인정보 프레임 검사

- [ ] 설정 화면의 키·웹훅 영역을 프레임 단위로 확인한다.
- [ ] 우측 상단 계정 및 IP 영역을 확인한다.
- [ ] 모니터링 URL을 확인한다.
- [ ] 파일 선택 창에 개인 파일명이 나타나지 않는지 확인한다.
- [ ] 다운로드 트레이에 개인 파일이 나타나지 않는지 확인한다.
- [ ] 비밀정보, 개인정보 또는 내부 주소가 한 프레임이라도 읽히면 실패로 판정한다.
